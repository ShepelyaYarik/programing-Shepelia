**ОПИС ПРОГРАМИ**

**Функціональне призначення:** програма демонструє практичне застосування контейнерів та алгоритмів бібліотеки **STL** для керування гетерогенною колекцією поліморфних об'єктів. Вона повністю позбавлена рутинних низькорівневих операцій із виділенням пам'яті за рахунок використання `std::vector<Phone*>`. Завдяки інтеграції `std::sort`, `std::for_each` та лямбда-виразів архітектура проєкту відповідає концепціям сучасного безпечного програмування (Modern C++). Крім того, безпека доступу до даних тепер контролюється генерацією стандартних винятків `std::out_of_range`.

**Опис логічної структури:**

### src/entity.h / src/entity.cpp

Поліморфна ієрархія класів (`Phone`, `SmartPhone`, `ButtonPhone`, `FoldingPhone`) повністю зберегла свою структуру та логіку роботи з ЛР №20, включаючи віртуальний деструктор та патерн «Прототип» (`clone()`). Це доводить гнучкість раніше спроєктованої ООП-архітектури, яка легко адаптується під нові контейнери даних.

### src/list.h / src/list.hpp

Клас `List` було повністю рефакторизовано.

* Замість сирого масиву `Phone data` та поля `size_t size` тепер використовується один інкапсульований контейнер **`std::vector<Phone*> phones`**.
* **`void addPhone(Phone* phone, size_t pos = 0)`**: тепер використовує методи `.insert()` та `.push_back()`. Для безпечного зсуву ітератора `phones.begin() + pos` застосовано явне приведення типів `static_cast<ptrdiff_t>(pos)`, що запобігає виникненню попереджень компілятора `-Wconversion` через змішування знакових та беззнакових типів.
* **`void removePhone(size_t index)`**: спочатку перевіряє коректність індексу. Якщо індекс виходить за межі `phones.size()`, викликається `throw std::out_of_range`. Далі оператор `delete` очищає пам'ять об'єкта в купі, а метод `.erase()` видаляє саму комірку-вказівник із вектора, автоматично зсуваючи сусідні елементи з часовою складністю $O(1)$ для оператора `[]`.
* **`void sortByRam()`**: викликає швидке гібридне сортування `std::sort`, передаючи туди ітератори вектора та кастомну структуру-функтор `CompareByRam`, у якій перевантажено оператор круглі дужки `operator()`.
* **`getNonGrandpaButtonPhones()`**: виконує фільтрацію варіанта. Алгоритм `std::for_each` послідовно обходить масив, а анонімна лямбда-функція захоплює локальний список за посиланням `[&result]`, виконує `dynamic_cast<const ButtonPhone*>` та копіює потрібні об'єкти через `.clone()`.

**Обробка винятків:** у методах видалення, читання та оновлення моделей за індексом впроваджено конструкцію:

```cpp

    throw std::out_of_range("Індекс виходить за межі списку!");
}

```

**Важливі фрагменти програми:**

1. Реалізація структури-функтора для сортування в `src/list.hpp`:

```cpp
struct CompareByRam {
    /**
     * @brief Перевантажений оператор "круглі дужки" для порівняння двох вказівників на Phone.
     */
    bool operator()(const Phone* a, const Phone* b) const {
        if (!a || !b) return false;
        return a->getRamMb() < b->getRamMb();
    }
};

```

2. Метод додавання елемента з використанням безпечної арифметики ітераторів (`ptrdiff_t`):

```cpp
void addPhone(Phone* phone, size_t pos = 0) {
    if (!phone) return;
    if (pos == 0) {
        phones.insert(phones.begin(), phone); 
    } else if (pos >= phones.size()) {
        phones.push_back(phone); 
    } else {
        phones.insert(phones.begin() + static_cast<ptrdiff_t>(pos), phone);
    }
}

```

3. Логіка фільтрації кнопкових телефонів за допомогою `std::for_each` та лямбди з блоком захвату `[&result]`:

```cpp
List getNonGrandpaButtonPhones() const {
    List result;
    std::for_each(phones.begin(), phones.end(), [&result](const Phone* phone) {
        auto* btnPhone = dynamic_cast<const ButtonPhone*>(phone);
        if (btnPhone && !btnPhone->getIsGrandpaPhone()) {
            result.addPhone(btnPhone->clone());
        }
    });
    return result;
}

```

4. Безпечне видалення з контролем меж та генерацією винятку:

```cpp
void removePhone(size_t index) {
    if (index >= phones.size()) {
        throw std::out_of_range("Індекс виходить за межі списку!");
    }
    delete phones[index]; 
    phones.erase(phones.begin() + static_cast<ptrdiff_t>(index)); 
}

```

**ВИСНОВКИ**

Під час виконання лабораторної роботи №22 я детально опанував практичні аспекти використання **Standard Template Library (STL)**, навчився працювати зі стандартними алгоритмами, функторами та механізмами обробки виняткових ситуацій у C++.

Переведення гетерогенної колекції `List` на роботу з **`std::vector`** дозволило повністю позбутися громіздкого, низькорівневого ручного виділення пам'яті, копіювання масивів та ризику виходу за їхні межі. Робота з вектором показала високу ефективність доступу до елементів за індексом за константний час $O(1)$.

Я опанував застосування алгоритму **`std::for_each`** у поєднанні з **лямбда-виразами**. Використання блоків захвату контексту (зокрема захоплення зовнішніх змінних та об'єктів за посиланням `[&i]` та `[&result]`) дозволило замінити старі індексні цикли `for` сучасним, декларативним та ізольованим кодом. Створення структури-функтора **`CompareByRam`** із перевантаженим `operator()` та його інтеграція в алгоритм **`std::sort`** забезпечили швидке та архітектурно правильне сортування об'єктів без порушення константної безпеки (`const correctness`).

Впровадження генерації стандартних винятків **`std::out_of_range`** суттєво підвищило надійність та відмовостійкість програми, дозволивши гнучко перехоплювати помилки індексування на етапі виконання (run-time) за допомогою засобів тестування Google Test. Динамічний аналіз пам'яті за допомогою утиліти Valgrind підтвердив абсолютну чистоту роботи з купою, довівши, що поєднання STL-контейнерів із правильним викликом деструкторів повністю нівелює проблему витоків пам'яті.
