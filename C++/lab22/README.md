# Лабораторна робота №22. Стандартна бібліотека шаблонів (STL). Контейнери, алгоритми, функтори та обробка виняткових ситуацій

## Загальне завдання

Модернізувати попередню лабораторну роботу №20 (поліморфна ієрархія класів) для повного переходу від низькорівневого ручного керування пам'яттю до використання засобів **Standard Template Library (STL)** та впровадження механізмів обробки виняткових ситуацій:

* **Повністю відмовитися від ручного керування динамічною пам'яттю** у класі-списку `List`. Очистити код від сирих двовимірних масивів `Phone data`, ручних лічильників розміру `size` та низькорівневих циклів реаллокації пам'яті (`new Phone*[...]`, `delete[]`).
* **Перевести гетерогенний контейнер `List` на роботу з послідовним контейнером `std::vector<Phone*>**`. Забезпечити стабільний доступ до елементів за константний час $O(1)$.
* **Замінити ручні цикли обходу колекції стандартними алгоритмами STL**. Для виведення даних, підрахунку та фільтрації застосувати алгоритм **`std::for_each`** у поєднанні з анонімними **лямбда-виразами** та явним захватом контексту за посиланням.
* **Реалізувати нову обов'язкову функцію сортування колекції — `sortByRam()**`. Інтегрувати стандартний алгоритм сортування **`std::sort`**, розробивши кастомний об'єкт-функцію (структуру-функтор **`CompareByRam`**) з перевантаженим оператором виклику функції `operator()` для впорядкування пристроїв за зростанням оперативної пам'яті.
* **Впровадити безпеку доступу до даних за допомогою механізму винятків (Exceptions)**. У методах читання, видалення та модифікації за індексом генерувати стандартний виняток **`std::out_of_range`** у разі виходу за поточні межі вектора.
* **Оновити набір модульних тестів**, додавши перевірку валідності сортування за RAM та контроль генерації виняткових ситуацій за допомогою макросів `EXPECT_THROW` Google Test Framework.

**Додаткові обов’язкові умови виконання робіт:**

* Повна відмова від використання глобального простору імен (`using namespace std;`) на користь точкових імпортів.
* Повна відмова від C-бібліотек введення/виведення та рядків типу `char*`.
* Оформлення документації коду за допомогою утиліти Doxygen.
* Покриття розроблених методів модульними тестами (Google Test Framework) не менше ніж на 50%.
* Демонстрація повної відсутності витоків пам'яті (`0 leaks`) за допомогою утиліти Valgrind під час роботи з STL-контейнером.

## Структура проекту

* `uml.png` — графічна UML-діаграма класів, оновлена для відображення інтеграції контейнера `std::vector` та структури порівняння `CompareByRam`.
* `src/entity.h` / `src/entity.cpp` — опис та реалізація поліморфної ієрархії мобільних пристроїв та методів їх серіалізації.
* `src/list.hpp` — **повністю оновлений заголовний файл**, який тепер поєднує оголошення та inline-реалізацію класу `List` на базі `std::vector`. Містить структуру-функтор `CompareByRam`, логіку обробки винятків `std::out_of_range`, безпечну арифметику ітераторів через приведення типів `static_cast<ptrdiff_t>`, а також алгоритми `std::for_each` та `std::sort`.
* `src/main.cpp` — головний файл програми, що демонструє роботу з оновленим списком: додавання елементів через `insert`/`push_back`, сортування бази даних, фільтрацію варіанта за допомогою лямбд та перехоплення винятків у блоках `try-catch`.
* `test/test.cpp` — модульні тести (Google Test) для перевірки STL-логіки: контроль сортування за RAM, перевірка глибокого копіювання списку без ефекту зрізання типів та валідація генерації винятків `std::out_of_range` за допомогою `EXPECT_THROW`.
* `Makefile` — скрипт автоматизації компіляції (`clang++` із суворими прапорцями безпеки перетворення типів `-Wconversion`), тестування, аналізу витоків пам'яті Valgrind та генерації документації Doxygen.
* `Doxyfile` — конфігурація для генерації документації Doxygen.
