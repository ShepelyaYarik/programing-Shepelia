У класі-колекції `List` реалізувати метод обходу колекції відповідно до першого пункту індивідуального завдання: розрахувати загальний об’єм оперативної пам’яті всіх пристроїв у колекції.

**ОПИС ПРОГРАМИ**

**Функціональне призначення:** програма моделює предметну область «Мобільний телефон» з використанням базових концепцій ООП. Вона створює динамічну колекцію (масив вказівників на об'єкти `Phone`), яка дозволяє надійно зберігати пристрої в пам'яті, динамічно змінювати розмір контейнера при додаванні чи видаленні елементів, а також виконувати агрегацію даних (підрахунок сумарного об'єму оперативної пам'яті).

**Опис логічної структури:** проект розділено на модулі відповідно до структури директорій лабораторної роботи. Забезпечено повне приховування внутрішніх полів класів та контроль життєвого циклу об'єктів через логування.

### src/entity.cpp / src/entity.h

Файли містять оголошення та реалізацію структури `ScreenSize`, переліку `OperatingSystem` та базового класу `Phone`:
* Описано приватні поля, публічні гетери та сетери із забезпеченням константності для методів, що не змінюють стан об'єкта.
* Реалізовано три типи конструкторів (default, parameterized, copy) з обов'язковим використанням списків ініціалізації та деструктор. Кожен з них виводить інформаційне повідомлення в консоль для відстеження роботи програми.

### src/list.cpp / src/list.h

Цей модуль містить клас-колекцію `List`, що інкапсулює логіку управління динамічною пам'яттю. Для уникнення холостих викликів конструкторів за замовчуванням та підвищення швидкодії, внутрішнє сховище реалізоване як масив покажчиків на об'єкти (`Phone** data`).

**Методи класу `List`:**
* `List()` та `~List()` — конструктор занулює покажчик, а деструктор послідовно звільняє пам'ять з-під кожного створеного об'єкта `Phone` у купі через оператор `delete`, після чого очищує сам масив комірок (`delete[]`), що повністю унеможливлює витоки пам'яті.
* `void addPhone(const Phone& phone, size_t pos)` — приймає готовий об'єкт, створює його копію у купі та вставляє покажчик на нього у масив на задану позицію, виконуючи зсув інших елементів праворуч.
* `void removePhone(size_t index)` — видаляє об'єкт за індексом, звільняє виділену під нього пам'ять та зсуває залишок покажчиків вліво.
* `Phone& getPhone(size_t index)` та `const Phone& getPhone(size_t index) const` — перевантажені за константністю методи для отримання безпечного доступу до елементів масиву.
* `int getTotalRam() const` — метод обходу колекції, який сумує об'єм оперативної пам'яті всіх телефонів у списку.

### test/test.cpp

Модуль для автоматичного модульного тестування, написаний з використанням фреймворку **Google Test Framework**. Тести покривають:
* Правильність ініціалізації полів класу `Phone` та роботу його методів.
* Коректність додавання, вставки за довільним індексом та видалення елементів із класу `List`.
* Точність роботи алгоритму підрахунку загальної RAM.
* Генерацію винятків `std::out_of_range` при спробах виходу за межі масиву.
* Сценарії роботи з пустим контейнером та перевірку методів виводу інформації.

**Важливі фрагменти програми:**

1. Демонстрація списку ініціалізації в конструкторі з аргументами класу `Phone`:

```cpp
Phone::Phone(bool water, bool shock, const std::string& mod, int ram, int storage, ScreenSize screen, OperatingSystem osType)
    : isWaterproof(water), isShockproof(shock), model(mod), ramMb(ram), storageMb(storage), screenSize(screen), os(osType) {
    std::cout << "[Log]: Called Parameterized Constructor for Phone: " << model << std::endl;
}

```

2. Послідовне звільнення динамічної пам'яті у деструкторі класу `List` (захист від витоків):

```cpp
List::~List() {
    for (size_t i = 0; i < size; ++i) {
        delete data[i];
    }
    delete[] data;
}

```

3. Реалізація індивідуального методу обходу колекції для підрахунку ОЗУ:

```cpp
int List::getTotalRam() const {
    int totalRam = 0;
    for (size_t i = 0; i < size; ++i) {
        totalRam += data[i]->getRamMb();
    }
    return totalRam;
}

```

**ВИСНОВКИ**

Під час виконання лабораторної роботи №17 я здійснив перехід від процедурного стилю програмування мовою C до об'єктно-орієнтованого підходу в мові C++. Я успішно засвоїв та реалізував на практиці фундаментальний принцип ООП — інкапсуляцію, приховавши внутрішній стан об'єкта `Phone` за допомогою модифікатора доступу `private` та надавши контрольований інтерфейс через публічні гетери й сетери.

Мною було розроблено клас-колекцію `List`, який гнучко керує пам'яттю за допомогою операторів `new` та `delete`. Використання структури масиву покажчиків дозволило оптимізувати роботу програми, уникнути зайвих холостих викликів конструкторів і зробити логи життєвого циклу об'єктів максимально прозорими. Інструменти автоматичного аналізу та модульного тестування `Google Test` підтвердили високу якість коду (покриття >90%), стабільність обробки виняткових ситуацій (`std::out_of_range`) та повну відсутність витоків пам'яті. Весь проект успішно задокументовано у форматі Doxygen.
