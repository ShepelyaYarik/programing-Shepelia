**ОПИС ПРОГРАМИ**

**Функціональне призначення:** програма моделює предметну область «Мобільний телефон» з використанням парадигми ООП. Вона створює поліморфну колекцію (динамічний масив вказівників), яка дозволяє зберігати базові смартфони, кнопкові та складані телефони. Реалізовано автоматичне управління пам'яттю об'єктів, пошук конкретних типів пристроїв за допомогою механізму ідентифікації типів під час виконання (RTTI) та агрегацію даних.

**Опис логічної структури:** проект розділено на класи сутностей та клас-колекцію з дотриманням принципів інкапсуляції, успадкування та поліморфізму.

### src/entity.cpp / src/entity.h

Файли містять оголошення та реалізацію ієрархії класів:

* `MobilePhone` — базовий клас з віртуальним деструктором та віртуальним методом `print()`.
* `ButtonPhone` — клас-спадкоємець, що розширює базовий клас специфічними для кнопкових телефонів полями та перевизначає метод `print()`.
* `FoldablePhone` — клас-спадкоємець для сучасних складаних смартфонів.

### src/list.cpp / src/list.h

Цей модуль містить клас `PhoneList`, що інкапсулює логіку роботи з динамічним масивом вказівників на базовий клас (`MobilePhone`).

**Функції (Методи класу `PhoneList`):** * `PhoneList()` та `~PhoneList()`
* опис: конструктор виділяє початкову пам'ять для масиву вказівників. Деструктор відповідає за звільнення пам'яті кожного об'єкта (виклик `delete`) та самого масиву (виклик `delete[]`), запобігаючи витокам пам'яті.

* `void addPhone(MobilePhone* phone, size_t pos)`
* опис: приймає вказівник на створений поліморфний об'єкт та додає його в колекцію (з динамічним розширенням масиву при потребі).


* `void removePhone(size_t index)`
* опис: видаляє елемент за індексом, звільняє його пам'ять та зсуває залишок масиву вліво.


* `int calculateTotalRAM() const`
* опис: обходить усі елементи колекції та сумує значення, отримані через метод `getRamMB()`.


* `void printNonBabushkaButtonPhones() const` та `void printFoldablePhones() const`
* опис: використовують оператор `dynamic_cast` для перевірки належності вказівника до конкретного класу-спадкоємця і виводять відповідні об'єкти.



### test/test.cpp

Модуль для автоматичного тестування логіки класів, написаний з використанням **Google Test Framework**.

**Тести:** перелік тестових сценаріїв:

* `EntityTest.*`: перевірка правильної ініціалізації об'єктів базового класу та спадкоємців через конструктори, перевірка роботи гетерів.
* `PhoneListTest.AddPhoneAndCalculateTotalRAM`: перевірка додавання об'єктів різних типів та точності математичного підрахунку RAM.
* `PhoneListTest.RemovePhoneUpdatesRAM`: перевірка коректного зсуву елементів після видалення.
* `PhoneListTest.RemoveFromEmptyListThrows` / `RemoveOutOfBoundsThrows`: перевірка генерації винятків (`std::out_of_range`) при спробі доступу за невірним індексом.
* Тести для перевірки виконання методів виводу (підняття Coverage до >90%).

2. Звільнення пам'яті масиву вказівників у деструкторі класу-колекції:

```cpp
PhoneList::~PhoneList() {
    for (size_t i = 0; i < count; ++i) {
        delete phones[i]; 
    }
    delete[] phones;
}

```

3. Ідентифікація типу об'єкта під час виконання за допомогою `dynamic_cast`:

```cpp
void PhoneList::printFoldablePhones() const {
    for (size_t i = 0; i < count; ++i) {
        FoldablePhone* fp = dynamic_cast<FoldablePhone*>(phones[i]);
        if (fp != nullptr) {
            fp->print();
        }
    }
}

```

Під час виконання лабораторної роботи №17 я здійснив перехід від процедурного програмування мовою C до об'єктно-орієнтованого підходу у мові C++.
