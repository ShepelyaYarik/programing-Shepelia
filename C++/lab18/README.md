## Загальне завдання

Поширити попередню лабораторну роботу (варіант 18 — "Мобільний телефон") шляхом переходу на стандартні потоки C++ та додавання функціоналу роботи з файлами. 

Реалізувати наступний функціонал:
* Заміна застарілих C-функцій вводу/виводу (`printf`/`scanf`) на використання безпечних об'єктно-орієнтованих потоків `std::cin`/`std::cout`.
* Заміна всіх конкатенацій рядків на роботу з потоками в пам'яті за допомогою класу `std::stringstream`.
* Заміна старого методу виводу інформації на метод серіалізації, що повертає сформований текстовий рядок про стан об'єкта (`std::string toString() const`).
* Заміна методу вводу на метод десеріалізації, що приймає рядок із даними, обробляє його за допомогою делімітера та заповнює поля об'єкта (`void fromString(const std::string& data)`).
* Поширення класу-списку методами роботи з файлами за допомогою файлових потоків (`<fstream>`):
  1. `void readFromFile(const std::string& fileName)` — зчитування колекції з файлу (з обов'язковим попереднім очищенням списку для запобігання витокам пам'яті).
  2. `void writeToFile(const std::string& fileName)` — запис поточної колекції у текстовий файл.
* Повна відмова від використання C-бібліотек для роботи з рядками (`char*`) та перехід на `std::string`.
* Заборона використання глобального простору імен (`using namespace std;`). Дозволено лише точкові імпорти (наприклад, `using std::cout;`).
* Оформлення документації коду за допомогою Doxygen.
* Покриття коду модульними тестами (Google Test Framework) не менше ніж на 50%.
* Перевірка програми на відсутність витоків пам'яті за допомогою утиліти Valgrind.

## Індивідуальне завдання (Варіант 18)

Розробити клас **`Phone`**, який містить технічні характеристики пристрою, та клас-контейнер **`List`** для управління динамічним масивом покажчиків на телефони. Забезпечити збереження та відновлення стану цього списку з текстового файлу, використовуючи як розділювач полів вертикальну риску `|`.

## Структура проекту

* `src/entity.h` / `src/entity.cpp` — опис структури `ScreenSize`, переліку `OperatingSystem` та класу сутності `Phone`. Реалізація методів серіалізації `toString()` та десеріалізації `fromString()`.
* `src/list.h` / `src/list.cpp` — опис та реалізація класу-контейнера `List`, управління динамічною пам'яттю (виділення, копіювання, повне звільнення в `clear()`), а також робота з файловими потоками (`ifstream`/`ofstream`).
* `src/main.cpp` — головний файл програми, що демонструє роботу конструкторів (за замовчуванням, параметризованого, копіювання), додавання елементів у список та базове тестування методів.
* `test/test.cpp` — модульні тести (Google Test) для перевірки логіки серіалізації/десеріалізації через `|`, коректності читання/запису у файл та контролю виключних ситуацій.
* `Makefile` — скрипт для автоматизації збірки, запуску тестування, перевірки покриття (`llvm-cov`) та генерації документації.
* `Doxyfile` — конфігураційний файл для генерації документації Doxygen.

## Інструкція з компіляції та запуску

Для взаємодії з проектом використовуйте наступні команди автоматизованої збірки:

* `make run` — повне очищення, компиляція проекту за допомогою `clang++` та запуск демонстраційного додатка (`main.bin`).
* `make test` — збірка та запуск модульних тестів за допомогою Google Test, генерація звітів про покриття коду у форматі HTML (`dist/coverage.html`).
* `make leak-check` — запуск програми під керуванням утиліти `valgrind` для перевірки коректності керування пам'яттю та відсутності витоків.
* `make format` — автоматичне генерування документації Doxygen на основі коментарів у коді.
* `make clean` — видалення тимчасових файлів та папки `dist`.
