## Загальне завдання

Поширити попередню лабораторну роботу (варіант 18 — "Мобільний телефон") шляхом реалізації механізму перевантаження стандартних операторів C++ для покращення інтерфейсу взаємодії з класами.

Реалізувати наступний функціонал:
* **У базовому класі прикладної галузі (`Phone`) перевантажити:**
  1. Оператор присвоювання (`operator=`) для реалізації безпечного глибокого копіювання полів об'єкта.
  2. Оператори порівняння: два протилежних оператора (`operator==` та `operator!=`) для логічної перевірки еквівалентності сутностей.
  3. Оператори введення / виведення (`operator<<` та `operator>>`) як дружні (`friend`) функції для інтеграції сутності зі стандартними потоками.
* **У класі-списку (`List`) перевантажити:**
  1. Оператор індексування (`operator[]`) у константній та неконстантній версіях для забезпечення прямого та зручного доступу до елементів динамічного масиву за індексом.
  2. Оператори введення / виведення (`operator<<` та `operator>>`) з акцентом роботи як із консоллю, так і безпосередньо з файловими потоками.
* Повна відмова від використання глобального простору імен (`using namespace std;`) на користь точкових імпортів (наприклад, `using std::ostream;`).
* Повна відмова від C-бібліотек введення/виведення та рядків типу `char*` (виключно `std::string` та `<iostream>`/`<fstream>`).
* Оформлення документації коду за допомогою утиліти Doxygen.
* Покриття розроблених методів та операторів модульними тестами (Google Test Framework) не менше ніж на 50%.
* Демонстрація повної відсутності витоків пам'яті за допомогою утиліти Valgrind.

## Індивідуальне завдання (Варіант 18)

Модернізувати класи **`Phone`** та **`List`**, перевівши логіку порівняння, копіювання, індексування та файлового/консольного введення/виведення на перевантажені оператори. Забезпечити наскрізне читання та запис усього контейнера у текстовий файл за допомогою синтаксису потоків (`stream << list` та `stream >> list`).

## Структура проекту

* `src/entity.h` / `src/entity.cpp` — опис структури `ScreenSize`, переліку `OperatingSystem` та класу сутності `Phone`. Реалізація перевантажених операторів `=`, `==`, `!=`, а також дружніх операторів потокового вводу/виводу `<<` та `>>`.
* `src/list.h` / `src/list.cpp` — опис та реалізація класу-контейнера `List`, управління динамічною пам'яттю (виділення, повне звільнення в `clear()`), перевантаження константного і неконстантного оператора `[]` з генерацією виключення `std::out_of_range`, а також операторів потоків `<<` і `>>` для роботи зі списком.
* `src/main.cpp` — головний файл програми, що демонструє практичне застосування нових операторів: копіювання об'єктів, логічне порівняння моделей, модифікацію полів через `list[i].set...()` та збереження/завантаження колекції через файлові потоки.
* `test/test.cpp` — модульні тести (Google Test) для перевірки поведінки перевантажених операторів класу `Phone` та контейнера `List`, а також перевірки стійкості до виключних ситуацій.
* `Makefile` — скрипт для автоматизації збірки, запуску тестування, перевірки покриття (`llvm-cov`) та генерації документації.
* `Doxyfile` — конфігураційний файл для генерації документації Doxygen.

## Інструкція з компіляції та запуску

Для взаємодії з проектом використовуйте наступні команди автоматизованої збірки:

* `make run` — повне очищення, компіляція проекту за допомогою `clang++` та запуск демонстраційного додатка (`main.bin`).
* `make test` — збірка та запуск модульних тестів за допомогою Google Test, генерація звітів про покриття коду у форматі HTML (`dist/coverage.html`).
* `make leak-check` — запуск програми під керуванням утиліти `valgrind` для перевірки коректності керування динамічною пам'яттю та відсутності витоків.
* `make format` — автоматичне генерування документації Doxygen на основі коментарів у коді.
* `make clean` — видалення тимчасових файлів та папки `dist`.
